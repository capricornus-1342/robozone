# План развития реализации проекта (r-03, сортировочный центр)

Основание: `src\specs\Проектирование сортирововчного центра.txt`.
Подход: снизу вверх — от самых простых, базовых модулей к объединению их в крупные детали.
Правила:
- переход к следующему этапу — только с разрешения пользователя;
- каждый этап сопровождается циклом вопросов по улучшению реализации;
- пункт помечается `[ ]` (не выполнен) или `[+]` (выполнен);
- артефакты каждого этапа создаются в `src\r-03\artefacts\<промпт этапа>`;
- противоречия и неточности, найденные на любом этапе, заносятся в `src\r-03\contradictions-report.md`.

[+] 0.1. Создать файл отчёта о противоречиях и неточностях `src\r-03\contradictions-report.md` (требование проектирования, п. «Создать файл с отчётом о противоречиях»).

## Этап 1. Анализ статических компонентов
[+] 1.1. Перечислить статические компоненты системы (оборудование, ворота, накопители, персонал), которые перемещают товары/ящики/паллеты, и их количество.
[+] 1.2. Классифицировать типы потоков: постоянные и вычисляемые.
[+] 1.3. Сверить с `src\specs\Robozone Task 1.txt`, описать противоречия и неточности.
[ ] 1.4. Ответить на вопросы по улучшению и получить разрешение на этап 2.

## Этап 2. Анализ динамических компонентов
Промпт: `src\r-03\prompts\20-component-dynamic.txt`
[+] 2.1. Перечислить динамические компоненты (товары, ящики, паллеты, роллтейнеры, грузовики, люди) и их параметры (размеры, массы) — только явно заданные в ТЗ/спецификации.
[+] 2.2. Классифицировать компоненты: главные/второстепенные, входные/выходные.
[+] 2.3. Описать потоки движения динамических компонентов между зонами и статическими компонентами.
[+] 2.4. Сверить с ТЗ и спецификацией, зафиксировать противоречия; ответить на вопросы по улучшению и получить разрешение на этап 3.

## Этап 3. Входные данные и параметры модели
Промпт: `src\r-03\prompts\40-data-input.txt`
[+] 3.1. Определить исходные данные (потоки, производительности, площади) по спецификации — только явно заданные, с указанием источника.
[+] 3.2. Зафиксировать недостающие параметры (раздел 3.4 спецификации) как «не задано (расчёт/калибровка позже)».
[+] 3.3. Сгруппировать данные по категориям и оформить набор данных для расчётов и симуляции; сверить с ТЗ, обновить отчёт о противоречиях.

## Этап 4. Выходные данные и метрики
Промпт: `src\r-03\prompts\50-data-output.txt`
[+] 4.1. Определить выходные метрики (загрузка участков, очереди, dwell time, пропускная способность) — с единицами, способом получения и источником в спецификации.
[+] 4.2. Сгруппировать метрики по категориям; определить критерии сравнения вариантов и KPI; сверить с ТЗ, обновить отчёт о противоречиях.

## Этап 5. Планировка и зоны
[ ] 5.1. Определить зоны, размеры и положения статических компонентов.
[ ] 5.2. Составить таблицу площадей и позиционирование оборудования.

## Этап 6. Диаграмма потоков (plantuml)
[ ] 6.1. Создать plantuml-диаграмму потоков движения динамических компонентов между зонами.
[ ] 6.2. Основной поток в центре, дополнительные вокруг; цветовая значимость потоков.

## Этап 7. SVG-чертёж статических компонентов
[ ] 7.1. Создать svg-чертёж с соблюдением размеров и положений статических компонентов.
[ ] 7.2. Обозначить потоки движения динамических компонентов и позиции в зонах.

## Этап 8. Программная имитационная модель
[ ] 8.1. Реализовать html/js имитационную модель с итерационным перемещением динамических компонентов.
[ ] 8.2. Правила этапов итерации задать отдельными правилами (шаг по кнопке пользователя, точный расчёт величин на следующий шаг).
[ ] 8.3. Отобразить накопление хранилищ, количество товаров на входе/выходе зон.

## Этап 9. Объединение и проверка
[ ] 9.1. Связать все модули: данные → расчёты → диаграммы → симуляция.
[ ] 9.2. Проверить целостность, согласованность и корректность итоговой модели.
