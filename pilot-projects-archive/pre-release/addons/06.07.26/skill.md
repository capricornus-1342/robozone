# SKILL: Имитационная модель сортировочного центра (СЦ) на HTML+JS

## ЦЕЛЬ СКИЛЛА

Создать полноценную интерактивную имитационную модель сортировочного центра (СЦ) с балансировкой потоков, визуализацией и сбором статистики, работающую в браузере на HTML + JavaScript (используется Canvas/2D для визуализации). Модель должна отражать все ключевые компоненты, процессы и логику управления, описанные в спецификации. Результат — готовый к запуску HTML-файл (или набор файлов), который можно открыть в браузере. Все файлы проекта должны быть размещены в поддиректории `app` относительно корня репозитория или рабочей папки.

## 1. ТРЕБОВАНИЯ К СИСТЕМЕ

### 1.1. Базовые сущности (классы)

Реализовать следующие классы:

| Класс | Описание |
| :--- | :--- |
| **Truck** | Входящий или исходящий грузовик. Свойства: `id`, `type` ('incoming'\|'outgoing'), `load` (массив объектов Box/Pallet/Item), `arrivalTime`, `scheduledTime`, `capacity` (для исходящих), `destRegion` (для исходящих). Методы: `unload()`, `load(boxes)`, `depart()`. |
| **Pallet** | Паллета с коробками. Свойства: `id`, `weight`, `numBoxes`, `destRegions` (массив). Метод: `unpack()` — возвращает массив объектов Box. |
| **Box** | Коробка с товарами. Свойства: `id`, `weight`, `destRegion`, `isOnPallet` (флаг). |
| **Item** | Отдельный товар (без упаковки). Свойства: `id`, `weight`, `destRegion`, `fragile`. |
| **ConveyorBelt** | Конвейерная линия (может быть несколько: телескопический, основной сортировочный, роликовые). Свойства: `id`, `speed` (шт/час), `buffer` (массив объектов, ожидающих обработки), `maxBuffer`. Метод: `process()` — обрабатывает объекты со скоростью `speed`, перемещает их на следующий узел. |
| **Dock** | Док (разгрузки или загрузки). Свойства: `id`, `type` ('unload'\|'load'), `currentTruck` (или null), `queue` (массив грузовиков). Метод: `assignTruck(truck)`, `free()`. |
| **Pocket** | Карман (выход сортировки). Свойства: `id`, `region`, `capacity` (макс), `boxes` (массив), `threshold` (порог для отправки). Метод: `addBox(box)`, `isReadyToShip()`. |
| **Buffer** | Буфер (промежуточный накопитель). Свойства: `id`, `maxCapacity`, `items` (массив). Метод: `add(item)`, `remove()`. |
| **SimulationEngine** | Главный управляющий модуль. Свойства: `time` (текущее время симуляции), `speed` (коэффициент ускорения), `isRunning`, `eventQueue` (список событий). Методы: `start()`, `pause()`, `step()`, `scheduleEvent(event, delay)`. |
| **StatisticsCollector** | Сбор статистики (реализовать класс или объект с методами). Методы: `logEvent(stage, entity, action, details)`, `generateSummary()`, `saveToJSON()`, `saveToCSV()` (использовать File System Access API). |
| **Worker** | Сотрудник СЦ. Свойства: `id`, `role` (driver, unloader, depalletizer, sorter, loader, dispatcher), `speed` (индивидуальная производительность), `currentTask` (текущая задача или null). Метод: `assignTask(task)`, `completeTask()`. |

### 1.2. Основные компоненты модели

Должны быть реализованы следующие функциональные блоки:

1. **Генератор входящего потока** — создаёт грузовики по расписанию (например, каждые 10–30 минут) с определённым составом (коробки, паллеты, отдельные товары). Распределение типов грузов — настраиваемое.
2. **Система назначения доков** — распределяет прибывающие грузовики по свободным докам разгрузки, иначе ставит в очередь.
3. **Разгрузка** — обработка грузовика с учётом типа груза (автоматическая/ручная). Разные скорости и ресурсы.
4. **Распаллетирование** — обработка паллет с преобразованием в коробки.
5. **Буферизация перед сортировкой** — промежуточный буфер с контролем заполненности.
6. **Сортировка** — направление коробок в карманы по региону. Использовать автоматический сортер с заданной пропускной способностью. **Конвейер должен быть кольцевым (петлевым)**, чтобы обеспечить максимальную плотность выходов и возможность обработки большого числа направлений.
7. **Накопление в карманах** — мониторинг заполненности, формирование партий.
8. **Формирование исходящих грузовиков** — по достижении порога в кармане — создание задания на отгрузку, вызов грузовика, загрузка.
9. **Балансировка потоков** — реализовать центральный регулятор, который на основе показателей загрузки принимает решения: замедление/ускорение конвейеров, изменение порогов отправки, перенаправление в резервный буфер, приостановка разгрузки.
10. **Резервный буфер временного хранения** — используется при переполнении карманов.
11. **Визуализация** — 2D-представление СЦ (на Canvas) с отображением: доков, конвейеров, карманов, буферов, перемещения объектов, текущей загрузки. **Конвейер должен быть визуально соединён с карманами** — от каждого кармана должна быть показана линия (желоб или стрелка), по которой коробки попадают из конвейера в карман, а при сбросе коробки анимируется её движение от конвейера к карману.
12. **Панель управления** — кнопки Старт/Пауза/Сброс, ползунок скорости, отображение текущего времени, статистики (онлайн-таблица).
13. **Экспорт статистики** — кнопка для сохранения отчёта в JSON или CSV с использованием `window.showSaveFilePicker`.

### 1.3. Персонал (ключевые роли)

В модели должны быть предусмотрены следующие роли сотрудников с их характеристиками:

| Роль | Обозначение в модели | Основные задачи | Ключевые параметры |
| :--- | :--- | :--- | :--- |
| **Водитель (входящий)** | `driver_in` | Пригоняет грузовик, ожидает разгрузки, оформляет документы. | `arrivalTime`, `waitingTime` |
| **Грузчик-приёмщик** | `unloader` | Снимает коробки с паллет или из кузова, кладёт на конвейер (ручной или автоматизированный). | `speed` (коробок/час), `unloadType` (manual/auto) |
| **Оператор распаллетирования** | `depalletizer` | Разбирает паллеты: снимает плёнку, достаёт коробки, проверяет целостность, передаёт на конвейер. | `speed` (коробок/час), `palletProcessingTime` (мин) |
| **Сортировщик (ручной)** | `sorter_manual` | Берёт коробки с конвейера и вручную ставит в нужный карман (в автоматическом режиме эту роль выполняет сортер). | `speed` (коробок/час) |
| **Грузчик-отгрузчик** | `loader` | Загружает отсортированные коробки из карманов в исходящий грузовик. | `speed` (коробок/час) |
| **Диспетчер** | `dispatcher` | Координирует расписание, принимает решения о регулировке потоков, оформляет документы. | `decisionTime` (мин) |

## 3. АЛГОРИТМЫ И ЛОГИКА

### 3.1. Дискретное событийное моделирование

Использовать событийную очередь. Каждое событие имеет время выполнения. Основные события:

- `ARRIVAL_TRUCK` — прибытие входящего грузовика.
- `UNLOAD_COMPLETE` — завершение разгрузки.
- `PALLET_UNPACK_COMPLETE` — завершение распаллетирования.
- `SORTING_STEP` — обработка одной коробки на сортировочном конвейере (можно пакетно).
- `POCKET_THRESHOLD_REACHED` — достижение порога в кармане.
- `SHIPMENT_LOAD_COMPLETE` — завершение загрузки исходящего грузовика.
- `BALANCE_CHECK` — периодическая проверка балансировки (каждые несколько секунд модельного времени).

Реализовать `SimulationEngine` с методом `run()` (или `step()`), который обрабатывает события по порядку.

**Улучшение:** Вместо бесконечного цикла `while` использовать `requestAnimationFrame` для управления тактами. Это позволит браузеру не зависать и плавно обновлять визуализацию.

### 3.2. Генератор входящего потока

Использовать распределение Пуассона для интервалов между прибытиями (средний интервал = 1 / интенсивность). Каждый грузовик генерирует состав: случайное количество паллет, коробок, отдельных товаров в соответствии с заданными долями.

**Улучшение:** Добавить возможность «пиковых» нагрузок — например, увеличение интенсивности в 2–3 раза в определённые периоды (утро, вечер, предпраздничные дни).

### 3.3. Балансировщик (WMS)

Реализовать функцию `balanceSystem()`, вызываемую периодически или при изменении состояний. Она анализирует:

- Заполненность промежуточного буфера (`buffer.fillRate`)
- Заполненность карманов (среднюю и максимальную)
- Загрузку доков разгрузки/загрузки
- Длину очередей грузовиков

На основе пороговых значений принимает решения (пример псевдокода):

```javascript
if (buffer.fillRate > 0.8) {
    reduceUnloadSpeed(0.7);
} else if (buffer.fillRate < 0.3) {
    increaseUnloadSpeed(1.0);
}

if (maxPocketFillRate > 0.8) {
    reduceSortingSpeed(0.8);
    lowerShipmentThreshold(0.5); // уменьшить порог для отправки
    if (maxPocketFillRate > 0.95) {
        redirectToReserveBuffer();
    }
}

if (loadDocksOccupied > 0.8 && pocketsReady > 0) {
    addExtraLoadWorkers(2);
}
Все регулировки должны быть плавными (или ступенчатыми) и логировать изменения для статистики.

Улучшение: Добавить возможность ручного вмешательства — например, кнопки для принудительного замедления/ускорения конвейеров, чтобы пользователь мог тестировать сценарии.

Слева — доки разгрузки (10 прямоугольников).

Линия конвейера от доков к центру.

Промежуточный буфер (прямоугольник с числом коробок).

Основной сортировочный конвейер — кольцевой (петлевой). Он должен быть изображён в виде замкнутой ленты, по которой движутся точки/коробки.

Карманы (30 ячеек) располагаются по внешнему или внутреннему периметру кольца, каждая подписана регионом, цвет заливки от зелёного к красному в зависимости от заполненности.

Конвейер должен быть визуально соединён с карманами: от каждого кармана должна быть показана линия (желоб или стрелка), по которой коробки попадают из конвейера в карман. При сбросе коробки анимируется её движение от конвейера к карману (коробка «съезжает» по наклонной линии).

Доки загрузки (5 прямоугольников) — на противоположной стороне от доков разгрузки, рядом с карманами.

Резервный буфер (отдельная область).

Анимировать движение коробок по конвейеру (можно просто перемещать точки по кольцу).

Обновлять статистику в реальном времени (текущее время, обработано коробок, загрузка карманов и т.д.).

Улучшение: Использовать requestAnimationFrame для анимации, чтобы движение было плавным и не зависело от тактов симуляции. Коробки можно отображать как цветные кружки, меняющие цвет в зависимости от региона. Для визуального соединения конвейера с карманами можно использовать линии со стрелками на конце, указывающими направление сброса.

3.5. Оптимальное расположение входов и выходов
Для обеспечения максимальной пропускной способности и минимизации заторов необходимо спроектировать пространственную структуру СЦ с учётом следующих принципов:

3.5.1. Входы (зоны подачи товаров на конвейер)
Расположение: Доки разгрузки должны быть сгруппированы на одной стороне здания (например, левой). Каждый док оснащён телескопическим конвейером, который подаёт коробки непосредственно на магистральный конвейер.

Количество: Количество доков разгрузки должно быть кратно числу грузчиков и скорости разгрузки, чтобы избежать очередей. В модели по умолчанию 10 доков.

Потоки: Все потоки от доков сходятся к единому промежуточному буферу, который выравнивает пиковые нагрузки и защищает сортировочный конвейер от переполнения.

Оптимизация: Буфер должен находиться в центре зоны разгрузки, чтобы длина конвейеров от каждого дока была примерно одинаковой. Это обеспечивает равномерное поступление коробок.

3.5.2. Выходы (карманы) с конвейера
Тип конфигурации: Для высокой производительности рекомендуется петлевая (кольцевая) схема основного сортировочного конвейера. Карманы располагаются по внешней стороне петли, что позволяет разместить до 100–200 выходов на сравнительно небольшой площади. Кольцевая конфигурация является обязательной для данной модели, так как она обеспечивает лучшую масштабируемость и равномерное распределение потоков.

Группировка по регионам: Карманы одного региона (например, «Москва», «Санкт-Петербург», «Казань») должны быть расположены компактно, чтобы при загрузке исходящих грузовиков минимизировать перемещения грузчиков. В модели по умолчанию 30 карманов, их можно разбить на 5–6 региональных блоков.

Близость к докам загрузки: Карманы должны находиться как можно ближе к внешней стене, где расположены доки загрузки. Это сокращает время транспортировки коробок от кармана до грузовика. В идеале каждый региональный блок карманов должен иметь свой выход на док загрузки.

Резервные карманы: Несколько карманов (обычно 2–3) должны быть универсальными и использоваться как резервные при переполнении основных. Они также могут служить для временного хранения.

Расположение на чертеже: В визуализации карманы следует отображать в виде сетки (например, 5 рядов по 6 карманов), каждый подписан регионом. Цветовая индикация заполненности (зелёный <50%, жёлтый 50–80%, красный >80%) помогает оператору быстро оценить ситуацию.

3.5.3. Связь входов и выходов
Маршрутизация: WMS определяет для каждой коробки целевой карман на основе региона. Коробка движется по кольцевому конвейеру до тех пор, пока не достигнет нужного кармана, где срабатывает сбрасыватель (толкатель или направляющая стрелка).

Буферизация на конвейере: На самом конвейере не должно быть больших накоплений — все коробки должны проходить в потоке. Для этого на каждом кармане предусмотрен накопитель (вместимость 500 коробок), который принимает сбрасываемые коробки и удерживает их до отправки.

Избегание пересечений: Потоки коробок на конвейере не должны пересекаться с потоками грузчиков или исходящих грузовиков. Для этого используются надземные конвейерные галереи или подземные туннели (в модели это упрощённо, но визуально можно показать разные уровни).

3.5.4. Масштабируемость
При необходимости увеличения мощности можно добавить новые доки разгрузки и загрузки, а также расширить петлю конвейера, включив в неё дополнительные карманы. В модели это реализуется через изменение параметров конфигурации.

Детализация по этапам
ЭТАП 0: Прибытие и постановка в очередь
Грузовик прибывает и отмечается в системе. Система проверяет загрузку доков разгрузки:

Если есть свободный док → направляет туда.

Если все заняты → грузовик становится в электронную очередь на въезде.

В модели: Создаётся событие TruckArrival.

ЭТАП 1: Разгрузка (с учётом типа груза)
Случай A: Коробки (не на паллетах)

Подэтап	Действие	Кто	Время
A1. Выбор способа разгрузки	Если есть телескопический конвейер → автоматическая разгрузка. Если нет → ручная.	Система / руководитель	—
A2. Автоматическая разгрузка	Грузчик снимает коробку с полки и кладёт на ленту конвейера. Конвейер сам вывозит её наружу.	Грузчик (человек) + конвейер	2–5 сек на коробку
A3. Ручная разгрузка	Грузчик вручную вынимает коробки из кузова и кладёт на стационарный конвейер (или на тележку).	Грузчик (человек)	10–15 сек на коробку
В модели: Создаётся сущность Box из грузовика. Определяется тип разгрузки (unload_type = automatic | manual). Каждая коробка получает время задержки unload_time и попадает на конвейер.

Случай B: Паллеты

Подэтап	Действие	Кто	Время
B1. Разгрузка паллеты	Паллету выгружают из грузовика с помощью гидравлической тележки или погрузчика.	Грузчик	1–2 мин на паллету
B2. Транспортировка на участок распаллетирования	Паллету перевозят к зоне, где её разберут.	Грузчик / погрузчик	1–2 мин
B3. Распаллетирование	Оператор снимает стрейч-плёнку, снимает коробки с паллеты, проверяет их целостность.	Оператор распаллетирования	5–15 мин на паллету (в среднем 30 сек на коробку)
B4. Подача коробок на конвейер	Оператор кладёт каждую коробку на конвейер вручную.	Оператор	Мгновенно (переход в конвейер)

Подэтап	Действие	Оборудование	Время
2.1. Сканирование	Считывается штрихкод на этикетке.	Оптический сканер	0.5 сек
2.2. Взвешивание	Измеряется вес для подтверждения соответствия.	Динамические весы	0.5 сек

9. КЛЮЧЕВЫЕ УЗКИЕ МЕСТА ДЛЯ МОДЕЛИ
При моделировании и оптимизации следует обратить внимание на следующие потенциальные «бутылочные горлышки»:

Ручная разгрузка — лимитирует пропускную способность (до 400 коробок/час на одного грузчика).

Распаллетирование — если много паллет, это становится бутылочным горлышком.

Карманы — если их мало, они переполняются, конвейер останавливается.

Загрузка исходящих грузовиков — медленнее, чем разгрузка, если мало грузчиков.

Эти узкие места должны быть явно отражены в модели и служить объектами для экспериментов по оптимизации (например, увеличение числа грузчиков, добавление карманов, автоматизация ручных операций).

class SimulationEngine {
    constructor(config) {
        this.time = 0;
        this.speed = 1;
        this.isRunning = false;
        this.eventQueue = [];
        this.config = config;
        // Инициализация всех компонентов

    }

    scheduleEvent(event, delay) {
        const eventTime = this.time + delay;
        this.eventQueue.push({ ...event, time: eventTime });
        this.eventQueue.sort((a, b) => a.time - b.time);
    }

        if (this.eventQueue.length === 0) return false;
        const event = this.eventQueue.shift();
        this.time = event.time;
        this.processEvent(event);
        return true;
    }

    processEvent(event) {
        switch (event.type) {
            case 'ARRIVAL_TRUCK':
                this.handleArrival(event.truck);
                break;
            case 'UNLOAD_COMPLETE':
                this.handleUnloadComplete(event.truck);
                break;
            case 'PALLET_UNPACK_COMPLETE':
                this.handlePalletUnpackComplete(event.pallet);
                break;
            case 'SORTING_STEP':
                this.handleSortingStep(event.box);
                break;
            case 'POCKET_THRESHOLD_REACHED':
                this.handlePocketThreshold(event.pocket);
                break;
            case 'SHIPMENT_LOAD_COMPLETE':
                this.handleShipmentLoadComplete(event.truck);
                break;
            // ... другие события
        }
    }

    run() {
        while (this.isRunning && this.step()) {

        }

12. ОПТИМАЛЬНОЕ РАСПОЛОЖЕНИЕ ВХОДОВ И ВЫХОДОВ (ДОПОЛНИТЕЛЬНАЯ АРХИТЕКТУРНАЯ СПЕЦИФИКАЦИЯ)
Для обеспечения максимальной эффективности работы СЦ в модели должны быть заложены следующие пространственные принципы:

12.1. Расположение входов (зон подачи товаров на конвейер)
Локализация: Все доки разгрузки размещаются на одной длинной стене здания (например, слева). Это позволяет организовать прямые и короткие конвейерные линии от каждого дока к центральному накопительному буферу.

Количество и шаг: Между доками соблюдается расстояние не менее 4–5 метров, чтобы фуры могли свободно маневрировать. В модели это задаётся параметром dockSpacing.

Подача на конвейер: С каждого дока коробки поступают на линейный накопительный конвейер, который объединяет все потоки и подаёт их в промежуточный буфер. Такой подход обеспечивает равномерную загрузку буфера и предотвращает простои.

Распределение нагрузки: Если один док перегружен, WMS может перенаправить часть потока на соседний док (при наличии свободных грузчиков), но в модели это имитируется через динамическое изменение скорости разгрузки.

12.2. Расположение выходов (карманов) с конвейера
Конфигурация: Основной сортировочный конвейер выполняется в виде замкнутой петли (кольцевой). Карманы располагаются по внешней стороне петли, что позволяет разместить до 100–200 выходов без значительного увеличения длины здания. Кольцевая конфигурация является обязательной для данной модели.

Группировка по регионам: Карманы одного географического кластера (например, «Северо-Запад», «Центр», «Юг») должны быть сгруппированы в блоки по 5–10 штук. Блоки разделены проходами для грузчиков.

Расстояние до доков загрузки: Каждый блок карманов должен находиться максимально близко к соответствующим докам загрузки, расположенным на противоположной стене (справа). Идеально, если блок карманов и док загрузки находятся на одной линии, чтобы сократить путь перемещения коробок.

Индикация заполненности: На визуализации карманы отображаются в виде ячеек с цветовой шкалой (от зелёного к красному). При достижении порога 80% карман подсвечивается жёлтым, при 95% – красным, и система автоматически инициирует отправку партии.

Резервные карманы: Предусмотреть 2–3 универсальных кармана, которые могут использоваться для любого региона в случае переполнения основных. Они располагаются в конце петли.

Визуальная связь с конвейером: В визуализации необходимо показать физическое соединение конвейера с карманами — линии, стрелки или желоба, демонстрирующие траекторию сброса коробок. Это делает модель более наглядной и приближенной к реальности.

12.3. Взаимосвязь входов и выходов в модели
Маршрутизация: WMS для каждой коробки рассчитывает кратчайший путь от входа до целевого кармана. В петлевой системе это время зависит от текущей загрузки конвейера и расстояния до кармана.

Буферизация на конвейере: Сам конвейер не должен служить накопителем. Все коробки должны сбрасываться в карманы как можно быстрее. Для этого в модели можно использовать многопоточную обработку, где несколько сбрасывателей работают параллельно.

Противозаторная логика: При превышении допустимой загрузки конвейера (например, > 80% от максимальной пропускной способности) WMS снижает скорость подачи из промежуточного буфера и временно направляет часть коробок в резервный буфер.

12.4. Масштабируемость расположения
Модель должна позволять легко изменять количество доков, карманов и их взаимное расположение через параметры конфигурации. Это даст возможность тестировать различные архитектурные варианты (линейную, петлевую, двухуровневую) и выбирать оптимальный для заданных условий. По умолчанию рекомендуется кольцевая схема, как наиболее производительная.
