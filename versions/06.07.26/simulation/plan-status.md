## ✅ Шаг 2 — Движок симуляции (DES) и событие прибытия грузовика

**Файлы:** `classes/SimulationEngine.js`, `app.js`

**Реализовано:**
- Класс `SimulationEngine`:
  - `scheduleEvent(delay, handler)` — добавление в очередь с сортировкой по времени
  - `step()` — извлечение и выполнение ближайшего события

  - Планируется каждые 0.5–1.5 мин модельного времени
  - Генерирует грузовик, подсвечивает случайный док, логирует
  - Автоматически перепланирует следующее прибытие
- Кнопки панели управления подключены: Старт, Пауза, Сброс (блокируются корректно)

## ✅ Шаг 4 — Приемка: буфер, доки, разгрузка

**Файлы:** `classes/Dock.js`, `classes/Buffer.js`, `simulation.js`, `visualization.js`, `app.js`, `index.html`

**Реализовано:**
- **Dock** (`classes/Dock.js`) — id, type (unload/load), currentTruck, queue, isBusy, assignTruck(), free()

- **Состояние приёмки** (`simulation.js`):
  - `Simulation.reception` — 10 доков + буфер на 185 палет
  - `findFreeDock()` — поиск свободного дока
- **Цикл обработки** (`app.js`):
  - Прибытие грузовика → поиск свободного дока → назначение
  - Расчёт времени разгрузки: `totalItems / throughputPerDock * 60` мин
  - Событие `UNLOAD_COMPLETE` — перемещение палет в буфер
  - Если док занят — грузовик становится в очередь дока
  - После завершения разгрузки — проверка очереди дока
  - Вызов `checkDepalletizing()` после добавления палет в буфер
- **Визуализация** (`visualization.js`):

- **Статус-бар**: Буфер X/185, Очередь доков: N

## ✅ Шаг 5 — Распаковка: распаллетизация, вскрытие КТЯ, поток тары

**Файлы:** `classes/Worker.js`, `simulation.js`, `visualization.js`, `app.js`, `index.html`

**Реализовано:**
- **Worker** (`classes/Worker.js`) — id, role, speed, currentTask, busy, assignTask(), completeTask()
- **Состояние распаллетизации** (`simulation.js`):
  - `Simulation.depalletizing` — 2 станции, очередь инфида, счётчики повторного использования/брака
  - `findFreeStation()` — поиск свободной станции
- **Цикл обработки** (`app.js`):
  - `checkDepalletizing()` — вызывается при добавлении палет в буфер и при завершении обработки
  - Берёт палету из буфера → назначает станции → планирует завершение через `timePerPalletSec`
  - `processDepalletizingStation()` — осмотр каждого КТЯ:
    - 80% → `containerReuseCount++` (повторное использование)
    - 20% → `containerScrapCount++`, `newContainerCount++` (брак → пресс → новые КТЯ)
    - Все товары из КТЯ → `infeedQueue[]`
  - После завершения — освобождение станции, проверка следующих палет
- **Визуализация** (`visualization.js`):
  - Зона распаллетирования: подсветка активных станций, счётчик занятых
  - Пресс: показывает количество утилизированных КТЯ
  - Новые КТЯ: показывает количество созданных
  - Стрелки потоков тары:
    - От распаллетирования → к конвейеру (КТЯ повторно, жёлтая линия)
    - От распаллетирования → к прессу (брак, красная линия)
    - От пресса → к новым КТЯ (новые, синяя пунктирная линия)
- **Статус-бар**: Инфид: N, КТЯ повторно: N, брак: N

## ✅ Шаг 6 — Сортировка: кольцевой конвейер, скаты, маршрутизация (Core Domain)

**Файлы:** `classes/ConveyorBelt.js`, `classes/Pocket.js`, `simulation.js`, `visualization.js`, `app.js`, `index.html`

**Реализовано:**
- **Pocket** (`classes/Pocket.js`) — id, capacity, threshold, items[], fillRate, isFull, isReadyToShip, addItem(), clear()
- **ConveyorBelt** (`classes/ConveyorBelt.js`) — id, throughput
- **Состояние сортировки** (`simulation.js`):
  - `Simulation.sorting` — 400 карманов (Pocket), очередь конвейера, счётчики
  - `getPocketAngle()` — расчёт угла кармана на кольцевой схеме
  - `getConveyorItemAngle()` — позиция точки на конвейере по прогрессу
- **Цикл сортировки** (`app.js`):
  - `scheduleSortingStep()` — событие каждые 0.1 мин модельного времени
  - `processSortingBatch()` — забор товаров из очереди инфида → сканирование (95% успех) → маршрутизация по destination → карман
  - NonSort (5% ошибок сканирования + `type === 'nonsort'`) → счётчик
  - Коэффициент эффективности 0.9 (efficiencyFactor) применяется к throughput
  - Создание визуальных точек на конвейере (1 на каждые 10 товаров, макс 600)
- **Анимация конвейера** (`app.js`):
  - `updateConveyor(deltaMin)` — движение точек по кольцу в onTick
  - Скорость: 0.4 прогресса/мин → точка проходит кольцо за ~2.5 мин
- **Визуализация** (`visualization.js`):
  - `drawConveyorItems()` — рисование движущихся голубых точек с glow-эффектом
  - `drawPocketBlocks()` — динамическая заливка карманов: зелёный (<50%), жёлтый (50–80%), красный (>80%)
- **Статус-бар**: отсортировано, на конвейере

## ✅ Шаг 7 — Упаковка: заполнение КТЯ, заклейка, паллетирование

**Файлы:** `simulation.js`, `visualization.js`, `app.js`, `index.html`

**Реализовано:**
- **Состояние упаковки** (`simulation.js`):
  - `Simulation.packing` — sealedCount, palletCount, lastProcessedPocket
  - `emptyContainerBuffer` добавлен в `Simulation.depalletizing` — пул пустых КТЯ
- **Поток тары** (`app.js`):
  - `processDepalletizingStation()` теперь инкрементирует `emptyContainerBuffer` (каждый распаллетированный КТЯ пополняет пул)
  - `schedulePackingStep()` — событие каждые 0.2 мин
  - `processPackingBatch()` — проход по карманам (15 за шаг):
    - Если в кармане ≥27 товаров и есть пустой КТЯ → взять 27 товаров
    - Употребить КТЯ из `emptyContainerBuffer`
    - Инкрементировать `sealedCount`
    - Каждые 16 КТЯ → +1 `palletCount`
- **Визуализация** (`visualization.js`):
  - Зона «ЗАКЛЕЙКА» справа от кольца — показывает количество заклеенных КТЯ
  - Зона «ПАЛЛЕТЫ» — количество сформированных палет
  - Зоны «ПРЕСС» и «НОВЫЕ КТЯ» перенесены на левую нижнюю часть
  - Стрелки потоков тары перерисованы под новое расположение
- **Статус-бар**: пустых КТЯ, заклеено, палет готово

## ✅ Шаг 9 — Отгрузка: буфер, ворота, загрузка машин

**Файлы:** `simulation.js`, `visualization.js`, `app.js`, `index.html`

**Реализовано:**
- **Состояние отгрузки** (`simulation.js`):
  - `Simulation.shipping` — буфер (палеты), 24 ворот, счётчик отправленных машин
  - `initShipping()` — инициализация dock-объектов со статусом `free`
  - `findFreeDock()` — поиск свободных ворот
- **Поток палет на отгрузку** (`app.js`):
  - При создании каждых 16 КТЯ в `processPackingBatch()` → палета в `shipping.buffer`
  - `scheduleShippingStep()` — событие каждые 1.0 мин
  - `processShipping()` → проверка буфера ≥16 палет → свободные ворота → загрузка 2 часа → отправление
  - После отправления: `dispatchedCount++`, ворота `free`
- **Визуализация** (`visualization.js`):
  - `drawShippingBuffer()` — зона «БУФЕР ОТГРУЗКИ» между кольцом и воротами (счётчик палет)
  - `drawLoadingDocks()` — статус ворот: зелёный (свободно), жёлтый (загрузка), зелёная рамка (отправлено)
  - Под воротами: «Отгружено: N»
  - Линии конвейера разбиты на два сегмента: кольцо → буфер отгрузки → ворота
- **Статус-бар**: Буфер отгрузки, Загрузка ворот, Отгружено машин

## ✅ Шаг 10 — Балансировщик потоков (WMS-регулятор)

**Файлы:** `simulation.js`, `visualization.js`, `app.js`, `index.html`

**Реализовано:**
- **Состояние регулятора** (`simulation.js`):
  - `Simulation.adjustments` — unloadSpeedFactor, sortSpeedFactor, conveyorSpeedFactor, pocketThresholdFactor, unloadPaused
  - `Simulation.balanceSystem(logFn)` — вызывается каждые 3 мин модельного времени
- **Правила регулировки**:
  - Буфер >90% → разгрузка приостановлена (unloadPaused=true, arrivals rate снижен)
  - Буфер >80% → unloadSpeedFactor ×0.9 (мин 0.3)
  - Буфер <30% → unloadSpeedFactor ×1.1 (макс 1.0)
  - Карманы >95% → sortSpeedFactor ×0.85, conveyorSpeedFactor ×0.8
  - Средняя заполненность карманов >80% → sortSpeedFactor ×0.9
  - Каскад: инфид >200 + сортировка <0.7 → разгрузка ×0.9
  - Все изменения логируются в консоль
- **Применение факторов** (`app.js`):
  - `startUnload()` — throughput скорректирован на unloadSpeedFactor
  - `processSortingBatch()` — throughput скорректирован на sortSpeedFactor
  - `updateConveyor()` — скорость конвейера скорректирована на conveyorSpeedFactor
  - `scheduleTruckArrival()` — при unloadPaused интервал увеличен до 3–4 мин
- **Визуализация** (`visualization.js`):
  - Индикаторы скорости (Разгр, Сорт, Конв) в виде шкал справа от кольца
  - Предупреждения регулятора (до 3 шт, красные) над кольцом
- **Статус-бар**: Разгр, Сорт, Конв в процентах
