# Спецификация имитационной модели сортировочного центра

**Domain-Driven Design — Аналитическая модель**

Сортировочный центр | 100 000 товаров/ч | 400 направлений

> **Требование к отчётности и аналитической модели:**
> Работа над решением начинается с построения аналитической модели, которая отражается в отдельном отчёте.
> Отчёт должен содержать: схему сортировочного центра с указанием площадей операций,
> расчёт производительности по каждой операции, аналитические выкладки и обоснование принятых решений.
> Команда вправе сдать решение в виде аналитической модели и отчёта без разработки полной симуляции.
> Симуляция, модель или иные программные материалы без отчёта и аналитической части
> к рассмотрению не принимаются.

## 1. Ограниченные контексты (Bounded Contexts)

Система разделена на 6 ограниченных контекстов, каждый со своей моделью и единым языком.

| Контекст | Описание |
|----------|----------|
| **Приемка** (Reception) | Входной транспорт, буфер приемки, регистрация палет, назначение доков |
| **Распаковка** (Depalletizing) | Распаллетизация, удаление стрейч-пленки, вскрытие КТЯ, осмотр, подготовка к сортировке |
| **Сортировка** (Sorting) | Автоматическая сортировка по 400 направлениям, кольцевой конвейер, скаты, обработка NonSort |
| **Упаковка** (Packing) | Укладка в КТЯ, уплотнение, заклейка, паллетирование |
| **Отгрузка** (Shipping) | Буфер отгрузки, загрузка машин, доковые ворота, отправление |
| **Управление тарой** (Container Mgmt) | Оборот КТЯ (80% reuse), брак (20%), пресс, машина новых КТЯ |

**Граничный контекст исключений** — сквозной контекст: NonSort-товары, повреждённые КТЯ, ошибки сканирования, сбои оборудования — обрабатываются на каждом этапе через выделенные каналы возврата.

## 2. Поддомены (Subdomains)

| Тип | Поддомен |
|-----|----------|
| **Core Domain** | Автоматическая сортировка товаров по направлениям; маршрутизация по 400 скатам; управление потоком 100 000 тов/ч; балансировка потоков (WMS-регулятор) |
| **Supporting** | Приемка и регистрация входящего потока; распаллетизация и вскрытие тары; укладка и заклейка КТЯ; паллетирование и отгрузка |
| **Generic** | Управление оборотом тары (80% reuse); учёт брака и производство новых КТЯ; планирование загрузки машин; сбор статистики |

## 3. Единый язык (Ubiquitous Language)

| Термин | Определение |
|--------|-------------|
| **Товар (Item)** | Единица отправления. ≤320 мм, ≤10 кг. Имеет направление, категорию (normal/nonsort), штрихкод. Форма: коробка, цилиндр, конверт, мягкий пакет |
| **КТЯ (Container)** | Картонный тарный ящик 600×400×400 мм. Вмещает до 27 товаров. Основная единица перемещения |
| **Палета (Pallet)** | Деревянный поддон 800×1200 мм. 20 КТЯ (вход) / 16 КТЯ (выход) |
| **Направление (Destination)** | Один из 400 городов/кластеров доставки. ID 1–400, доля потока (80/20 по Парето, распределение Zipf) |
| **Сортировщик (Sorter)** | Автоматическая машина сортировки. Производительность 10 000 тов/ч. Кольцевой конвейер. Оборудование: многоракурсные сканеры, станции взвешивания, 3D-сортеры, узколенточные сортеры |
| **Инфид (Infeed)** | Зона загрузки товаров на сортировщик. Оператор подаёт товары на ленту (1 000 тов/ч). При автоматической загрузке ограничение оператора снимается |
| **Скат (Chute)** | Выходной накопитель сортировщика для одного направления |
| **NonSort** | Товар, не подлежащий автоматической сортировке. Причины: нестандартная форма (цилиндр, мягкий пакет), хрупкость, негабарит (>320 мм), нечитаемый/повреждённый штрихкод, повреждённая упаковка, отсутствие маршрута. Направляется на ручную обработку с возможностью возвратного потока после ручной коррекции |
| **Ролл-кейдж (RollCage)** | Клетка на колёсах для крупногабаритных/NonSort товаров |
| **Волна (Wave)** | График отгрузки. Машина загружается 2 часа, 24 ворот |
| **Док (Dock)** | Место разгрузки/загрузки грузовика. Типы: unload, load |
| **Карман (Pocket)** | Накопитель сортировщика для одного направления. Имеет вместимость, порог отправки |
| **Буфер (Buffer)** | Промежуточный накопитель между участками. Приемка, резервный |
| **Грузовик (Truck)** | Входящий (с палетами) или исходящий (под загрузку) транспорт |
| **Балансировщик (Balancer)** | WMS-регулятор, управляющий скоростями и порогами на основе загрузки системы |

## 4. Классы модели

### 4.1. Базовые сущности

| Класс | Описание |
| :--- | :--- |
| **Truck** | Входящий или исходящий грузовик. Свойства: `id`, `type` ('incoming'\|'outgoing'), `load` (массив Pallet/Box/Item), `arrivalTime`, `capacity` (для исходящих), `destRegion`. Методы: `unload()`, `load(boxes)`, `depart()` |
| **Pallet** | Палета с КТЯ. Свойства: `id`, `containers` (массив Container), `maxSlots` (20 вх/16 вых). Метод: `unpack()` — возвращает массив Container |
| **Container (КТЯ)** | Картонный тарный ящик. Свойства: `id`, `items[]`, `maxCapacity=27`, `maxWeight=30kg`, `status` (empty\|filling\|full\|sealed), `isReusable`. Методы: `addItem()`, `seal()`, `inspect()` |
| **Box** | Коробка с товарами. Свойства: `id`, `weight`, `destRegion`, `destId` |
| **Item** | Товар. Свойства: `id`, `weight`, `destRegion`, `destId`, `type` (normal\|nonsort), `barcode`, `fragile` |
| **ConveyorBelt** | Конвейерная линия. Свойства: `id`, `type` (telescopic\|main\|roller), `speed` (шт/ч), `buffer` (массив), `maxBuffer`. Метод: `process()` |
| **Dock** | Док разгрузки/загрузки. Свойства: `id`, `type` ('unload'\|'load'), `currentTruck`, `queue` (массив Truck). Методы: `assignTruck(truck)`, `free()` |
| **Pocket** | Карман сортировки. Свойства: `id`, `region`, `capacity` (макс), `boxes` (массив), `threshold` (порог отправки), `fillRate`. Метод: `addBox(box)`, `isReadyToShip()` |
| **Buffer** | Буфер (промежуточный накопитель). Свойства: `id`, `maxCapacity`, `items` (массив), `fillRate`. Методы: `add(item)`, `remove()` |
| **Worker** | Сотрудник СЦ. Свойства: `id`, `role` (driver\|unloader\|depalletizer\|sorter\|loader\|dispatcher), `speed` (инд. производительность), `currentTask`. Методы: `assignTask(task)`, `completeTask()` |
| **SimulationEngine** | Главный управляющий модуль. Свойства: `time`, `speed` (коэфф.), `isRunning`, `eventQueue`. Методы: `start()`, `pause()`, `step()`, `scheduleEvent(event, delay)`, `run()` |
| **StatisticsCollector** | Сбор статистики. Методы: `logEvent(stage, entity, action, details)`, `generateSummary()`, `saveToJSON()`, `saveToCSV()` |

## 7. Бизнес-процессы

### 7.1 Приемка палет

Входящий поток: 185 палет/ч при 20 КТЯ на палете (3 700 КТЯ/ч = 100 000 тов/ч).
Буфер приемки рассчитан на 185 палет — ровно один час работы при полной загрузке.

```
Машина прибывает → Назначение дока → Разгрузка в буфер приемки (185 палет/ч) → Регистрация в WMS
```

| Действие | Событие | Описание |
|----------|---------|----------|
| Въезд машины | `TruckArrived` | Машина с палетами прибывает к воротам приемки |
| Назначение дока | `DockAssigned` | Система назначает свободный док (из 10) или ставит в очередь |
| Разгрузка | `PalletsUnloaded` | 185 палет/ч (3 700 КТЯ/ч) перемещаются в буфер приемки |
| Регистрация | `LotRegistered` | Каждая палета сканируется, привязывается к партии |
| Ожидание | `LotQueued` | Палета помещается в очередь на распаллетизацию |

### 7.2 Распаковка и вскрытие

```
Палета из буфера → Удаление стрейч-пленки → Снятие КТЯ с палеты → Осмотр КТЯ → Вскрытие КТЯ → Товары к инфиду
```

| Действие | Событие | Описание |
|----------|---------|----------|
| Распаллетизация | `PalletDepalletized` | Пленка и лента удалены, 20 КТЯ сняты с палеты |
| Осмотр КТЯ | `ContainerInspected` | 80% КТЯ → повторное использование |
| Вскрытие | `ContainerOpened` | КТЯ вскрыт, товары извлечены (27 шт) |
| Поток тары | `ContainerRouted` | Пустые КТЯ: 80% → повторно, 20% → брак (пресс) |

### 7.3 Автоматическая сортировка (Core Domain)

```
Загрузка на инфид → Сканирование штрихкода → Маршрутизация → Движение по кольцевому конвейеру → Сброс на скат #N
```

**Параметры:** Сортировщик 10 000 тов/ч × 10 шт = 100 000 тов/ч | 400 направлений | Кольцевой (петлевой) конвейер

| Действие | Событие | Описание |
|----------|---------|----------|
| Загрузка на сортировщик | `ItemLoaded` | Товар помещён на ленту инфида оператором |
| Сканирование | `ItemScanned` | Штрихкод считан, направление определено |
| Ошибка сканирования | `ScanFailed` | Штрихкод не читается — товар в NonSort |
| Маршрутизация | `ItemRouted` | Система назначает скат по матрице маршрутизации |
| Движение по конвейеру | `ItemOnConveyor` | Товар движется по кольцевому конвейеру к целевому скату |
| Сброс на скат | `ItemDischarged` → Chute#N | Товар сброшен в накопитель направления N |
| Негабарит / NonSort | `NonsortDiverted` | Товар направлен на канал ручной обработки |

### 7.3.1 Анализ альтернативных сценариев сортировки

**Сценарий А: Ручная загрузка (базовый)**
10 сортировщиков × 10 000 тов/ч. На каждый сортировщик — 10 операторов инфида (1 000 тов/ч/чел).
Итог: 100 000 тов/ч. Ограничение: производительность оператора (1 000 тов/ч) может стать узким местом
при росте потока.

**Сценарий Б: Автоматическая загрузка (роботизированный инфид)**
При автоматической загрузке ограничение оператора снимается — сортировщик работает на полную мощность.
Количество сортировщиков: 100 000 / 10 000 = 10 (без изменений), операторы не требуются.
Производительность ограничивается исключительно пропускной способностью сортировщика.

**Сценарий В: Меньше сортировщиков с большей производительностью**
Например, 5 сортировщиков × 20 000 тов/ч = 100 000 тов/ч (при наличии соответствующего оборудования).

В модели должны быть реализованы все три сценария как переключаемые конфигурации.

### 7.3.2 Двухстадийная ручная сортировка (базовое сравнение)

Для обоснования автоматизации приводится базовый ручной сценарий:

**Стадия 1 — Предварительная сортировка (80% потока по Парето).**
Операторы распределяют товары по 80 основным направлениям (из 400).
Скорость ручного сортировщика: 250 тов/ч (sorter_manual).

**Стадия 2 — Досортировка (оставшиеся 20% товаров по 320 направлениям).**

**Расчёт персонала:**
- 100 000 тов/ч / 250 тов/ч = 400 операторов на стадию
- С учётом Парето: ~320 чел на стадию 1 + 80 чел на стадию 2 = ~400 чел
- С учётом неравномерности и замен: до 800 чел

Автоматизация (10 сортировщиков × 10 операторов = 100 чел) сокращает персонал в ~8 раз
по сравнению с ручным сценарием, что является ключевым обоснованием внедрения сортировочного оборудования.

### 7.4 Упаковка и паллетирование

```
Установка пустого КТЯ под скат → Заполнение товарами → Уплотнение → Съём со ската →
Транспортировка к заклейке → Заклейка (автомат, ~10 сек) → Установка на палету (до 16 КТЯ)
```

**Вспомогательные операции у сортировщика (снижают эффективную производительность):**
- Загрузка пустых КТЯ в сортировщик
- Выгрузка заполненной тары со ската
- Утряска товаров в частично заполненных КТЯ
- Подъём выпавших товаров с конвейера
- Удаление повреждённых коробок

В модели эти операции учитываются как потери времени (коэффициент эффективности ~0,85–0,95
в зависимости от сценария).

| Действие | Событие | Описание |
|----------|---------|----------|
| Подача пустого КТЯ | `EmptyContainerDeployed` | Пустой КТЯ устанавливается под скат |
| Заполнение | `ContainerFillProgress` | Товары накапливаются в КТЯ (до 27 или 30 кг) |
| Уплотнение | `ContainerCompacted` | Товары уплотнены |
| КТЯ заполнен | `ContainerFull` | |
| Транспортировка | `ContainerMoved` → SealLine | Заполненный КТЯ на линию заклейки |
| Заклейка | `ContainerSealed` | КТЯ заклеен скотчем (автомат, ~10 сек) |
| Паллетирование | `PalletBuilt` | КТЯ установлен на палету (до 16 КТЯ на палете вых.) |

### 7.5 Оборот тары и брак

```
Пустой КТЯ после распаковки → Осмотр:
  ├── 80% годен → Буфер пустых КТЯ → К сортировщику
  └── 20% брак → Пресс → Машина новых КТЯ → Новые КТЯ в буфер
```

| Действие | Событие | Описание |
|----------|---------|----------|
| Осмотр КТЯ | `ContainerInspected` | 80% → повторно, 20% → брак |
| Списание брака | `ContainerScrapped` | Повреждённые КТЯ — в пресс |
| Производство новых | `NewContainerCreated` | Машина формирует новые КТЯ взамен брака |
| Подача к сортировщику | `ContainerFedToSorter` | Пустые КТЯ подаются к скатам |

### 7.6 Отгрузка

Одна машина вмещает 32 палеты, из которых только 16 используются под КТЯ.
Оставшиеся 16 мест заняты ролл-кейджами с NonSort/крупногабаритными товарами.
Загрузка одной машины занимает 2 часа через 24 ворот.

```
Палета с КТЯ (16 шт) → Буфер отгрузки → Назначение ворот (1-24) →
Загрузка в машину (2ч) → 16 палет КТЯ + 16 ролл-кейджей → Отправление
```

| Действие | Событие | Описание |
|----------|---------|----------|
| Транспортировка к отгрузке | `PalletMovedToShipping` | Палета доставлена в буфер отгрузки |
| Назначение ворот | `DockAssigned` | Система назначает ворота (1-24) |
| Загрузка машины | `TruckLoading` | 16 палет КТЯ + 16 ролл-кейджей загружаются (2 часа) |
| Завершение загрузки | `TruckLoaded` | Машина полностью загружена (32 палеты) |
| Отправление | `TruckDispatched` | Машина покидает СЦ |

**Ограничение исходящего потока:** из-за того, что только 16 из 32 мест в машине
заняты КТЯ, эффективная вместимость по КТЯ составляет 16 палет × 16 КТЯ = 256 КТЯ на машину.

### 7.7 Обработка исключений (NonSort)

**Причины возникновения NonSort (5% от общего потока):**
1. **Негабарит** — товар крупнее 320 мм (физически не проходит в сортировщик)
2. **Нестандартная форма** — цилиндр, мягкий пакет, конверт — не фиксируются на конвейере
3. **Хрупкость** — требует ручной обработки для предотвращения повреждений
4. **Нечитаемый/повреждённый штрихкод** — система не может определить направление
5. **Множественное считывание** — два штрихкода на одном товаре
6. **Повреждённая упаковка** — товар рассыпается/деформирован
7. **Отсутствие маршрута** — направление не найдено в матрице маршрутизации

**Возвратный поток (после ручной обработки):**
```
Товар на сортировщике → Обнаружен NonSort → Канал отбраковки →
  ├── Ручная коррекция (штрихкод, упаковка) → Повторный прогон через сортировщик
  └── Не подлежит коррекции → Ручная сортировка → Ролл-кейдж → Загрузка в машину
```

NonSort-товары, прошедшие ручную коррекцию, возвращаются на сортировщик (повторный прогон).
Остальные направляются в ролл-кейджи и занимают 16 мест в машине, не используемых под КТЯ.

Типы исключений (Exception Events):
- `ScanFailed` — нечитаемый штрихкод
- `MultipleRead` — множественное считывание
- `OverSized` — негабарит (>320 мм)
- `DamagedPackage` — повреждённая упаковка
- `NoRoute` — отсутствие маршрута в матрице
- `FragileItem` — хрупкий товар

## 9. Алгоритмы и логика

### 9.1. Дискретное событийное моделирование (DES)

Событийная очередь. Основные события:

- `ARRIVAL_TRUCK` — прибытие входящего грузовика
- `UNLOAD_COMPLETE` — завершение разгрузки
- `PALLET_UNPACK_COMPLETE` — завершение распаллетирования
- `SORTING_STEP` — обработка коробки на сортировщике (пакетно)
- `POCKET_THRESHOLD_REACHED` — достижение порога в кармане
- `SHIPMENT_LOAD_COMPLETE` — завершение загрузки исходящего грузовика
- `BALANCE_CHECK` — периодическая проверка балансировки

`SimulationEngine` использует `requestAnimationFrame` для тактов (не блокирует браузер).

### 9.2. Генератор входящего потока

- Распределение Пуассона для интервалов между прибытиями
- Состав грузовика: случайное количество паллет, коробок, отдельных товаров
- Пиковые нагрузки: увеличение интенсивности в 2–3 раза в заданные периоды
- Распределение по направлениям: 80/20 по Парето (Zipf-распределение)
  — Для 400 направлений используется Zipf с параметром s ≈ 1.0–1.2:
    20% направлений (≈80 из 400) получают ~80% общего потока,
    остальные 320 направлений — ~20% потока.
  — Алгоритм: вес направления `i` = `1 / i^s`, нормировка на сумму всех весов.

### 9.3. Балансировщик потоков (WMS-регулятор)

Функция `balanceSystem()`, вызываемая периодически. Анализирует:

- Заполненность буфера приемки
- Заполненность карманов (среднюю и максимальную)
- Загрузку доков разгрузки/загрузки
- Длину очередей грузовиков
- Пропускную способность сортировщиков

**Правила регулировки:**

```
if (buffer.fillRate > 0.8)            → reduceUnloadSpeed(0.7)
if (buffer.fillRate < 0.3)            → increaseUnloadSpeed(1.0)
if (maxPocketFillRate > 0.8)          → reduceSortingSpeed(0.8), lowerThreshold(0.5)
if (maxPocketFillRate > 0.95)         → redirectToReserveBuffer()
if (loadDocksOccupied > 0.8 && ready) → addExtraLoadWorkers(2)
```

Все регулировки плавные (ступенчатые), логируются. Предусмотрено ручное вмешательство (кнопки принудительного замедления/ускорения).

**Каскадные эффекты (локальная деградация):**
Любая локальная деградация на участке каскадно влияет на вышестоящие участки контура:
- Затор на скате → блокировка сортировщика → остановка инфида → переполнение буфера → остановка приёмки
- Отказ сортировщика → перераспределение потока на остальные → их перегрузка → каскадное замедление
- Балансировщик отслеживает цепочки зависимостей и применяет упреждающую регулировку на 1–2 шага вверх по потоку

### 9.4. Вспомогательные операции у сортировщика (параметры)

| Операция | Среднее время | Влияние на throughput |
|----------|--------------|----------------------|
| Загрузка пустого КТЯ в сортировщик | 5–10 сек | Снижает эффективное время сортировки |
| Выгрузка заполненного КТЯ со ската | 10–15 сек | Простой ската на время замены |
| Утряска товаров в частично заполненном КТЯ | 3–5 сек | Микроостановка линии |
| Подъём выпавших товаров | 15–30 сек | Остановка сегмента конвейера |
| Удаление повреждённой коробки | 10–20 сек | Изъятие из потока |

Коэффициент эффективной производительности сортировщика: 0,85–0,95 (с учётом вспомогательных операций).

## 13. Узкие места (Bottlenecks)

| Участок | Потенциальное ограничение |
|---------|--------------------------|
| Ручная разгрузка | До 400 коробок/ч на грузчика |
| Распаллетирование | Бутылочное горлышко при высокой доле паллет |
| Оператор инфида | 1 000 тов/ч — узкое место при ручной загрузке (снимается при автоматизации) |
| Сортировщик | 10 000 тов/ч — ограничение пропускной способности (×10 = 100 000 тов/ч) |
| Карманы | Переполнение → блокировка сортировщика (каскадный эффект вверх по потоку) |
| Заклейка | Автомат ~10 сек/КТЯ — потенциальный затор при пиковых нагрузках |
| Загрузка исходящих | Медленнее разгрузки при дефиците грузчиков |
| NonSort | Ручная обработка ограничивает общую пропускную способность |
| Исходящие КТЯ | Только 16 из 32 мест в машине под КТЯ — ограничивает эффективный объём отгрузки |

## 14. Пространственная архитектура

### 14.1. Расположение входов
- Доки разгрузки — на одной стороне (левой), сгруппированы
- Расстояние между доками ≥4–5 м (`dockSpacing`)
- Телескопические конвейеры подают коробки на магистральный конвейер к буферу
- Буфер в центре зоны разгрузки (равномерная длина конвейеров)

### 14.2. Расположение выходов
- Сортировочный конвейер — кольцевой (петлевой)
- Карманы — по внешней стороне петли (до 100–200+ выходов)
- Группировка по регионам (блоки по 5–10 карманов)
- Близость к докам загрузки (противоположная сторона)
- 2–3 резервных (универсальных) кармана в конце петли

### 14.3. Масштабируемость
- Добавление доков/карманов через конфигурацию
- Расширение петли конвейера

### 14.4. Расчёт площадей операций
Для каждой зоны СЦ необходимо указывать занимаемую площадь:

| Зона | Расчёт площади |
|------|---------------|
| Приёмка | 10 доков × (ширина дока + 5 м маневрирования) × глубина зоны |
| Буфер приемки | 185 палет × 0,96 м²/палета (800×1200 мм) × коэфф. проходов 1,5 |
| Распаллетизация | 2 поста × 12 м²/пост |
| Сортировочный конвейер | Длина кольца × ширина конвейера (зависит от кол-ва карманов) |
| Зона скатов (400 карманов) | 400 × (ширина ската + зазор) |
| Упаковка и заклейка | 10 линий × 15 м²/линия |
| Буфер отгрузки | 24 ворот × 20 м²/ворота |
| Зона пресса и новых КТЯ | 50 м² |
| Административно-бытовые | 200 м² |

Площади указываются в отчёте и могут меняться в зависимости от конфигурации модели.
